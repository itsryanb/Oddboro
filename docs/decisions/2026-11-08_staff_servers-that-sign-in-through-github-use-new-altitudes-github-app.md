- [staff] **Decision (2026-11-08): a hosted server that signs in through GitHub, GitHub's own MCP server among them, signs in with New Altitude's own GitHub OAuth App, asking for `repo read:org read:user` only.** GitHub lets no app register itself, so the office's usual sign-in failed on the Desk (issue #64). An OAuth App, not a GitHub App, since it needs no install on each account or organization; GitHub has no scope that reads private repositories only, so the server's address and the Odd's grant hold what an Odd may do, as they do for every hosted tool. The office finds the server's sign-in server before it signs in (`knowServer` in `apps/office/src/lib/server/oauth.ts`), since the SDK picks scopes before it asks for the app and would otherwise ask for every scope GitHub's server lists. The app's id is in `oauth.ts`; its secret comes from the build (`ODDBORO_GITHUB_CLIENT_SECRET`, from the `OAUTH_GITHUB_CLIENT_SECRET` release secret) and never sits in the repo or the secret store. Its tokens expire after 8 hours and renew for 6 months unused. New Altitude provides only the sign-in and never receives a token. An organization that restricts OAuth Apps must approve it once. GitHub is one built-in catalog tool (`github`, GitHub's full server), and any `api.githubcopilot.com` address an Odd asks for becomes it with no key header, since an Odd that knew GitHub's server took tokens asked the owner to make one; the owner's own Takes a key still works.
