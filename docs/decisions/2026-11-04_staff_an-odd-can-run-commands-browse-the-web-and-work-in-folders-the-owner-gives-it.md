- [staff] **Decision (2026-11-04): an Odd can run commands, browse the web and work in folders the owner gives it, each set per Odd on its Settings tab, off by default, and held by each coding tool's own tools and walls.** Odds that build and research need a shell, the web and the owner's real projects, without a way out to the owner's keys. Run commands and Browse the web head the Settings tab's Office list; the Folders tab holds folders, picked or typed, at Can read or Can write (the 2026-11-05 picker ruling). The stored switch is the owner's choice; whether a run gets a shell is worked out per run from its tool and system (`commandsHow` in `agents.ts`), never written back. Claude Code follows the switch on a Mac, with `Bash` in its own sandbox: it writes only the folders the run writes, never the data folder or what the walls below refuse, and sees none of the secrets in the run's environment: the API key, `DATABASE_URL` and every name that says key, token, secret, password, credential, auth or cookie, but the office's own git settings. Claude Code itself and the office's tool server keep them. Off a Mac it shows off. Codex follows it where its sandbox held (the 2026-11-06 files ruling); Grok and Gemini show off, each saying why (`COMMANDS_WHY`). The staff PATCH refuses `{commands}` for a tool that does not follow the switch, so a stored yes is always the owner's own. Browse the web turns on each tool's own search and fetch (item 9 names them). What an Odd searches leaves the Mac by design, and the switch carries no warning line. Every tool's walls treat a granted folder as they treat the Odd's own folders: read, or read and written, with its instruction files never written, nor, in a granted folder alone, git's usual places anywhere in it (`REPO_RUNS`: hooks, the config file, submodules' copies), which git still reads. They do not stop every way a project's code can run later: a `.git` pointer file or `.git/commondir` naming a config elsewhere, a nested repository for Codex, or code in project files such as package scripts, a Makefile or tests. The owner looks at what an Odd changed before running that project's tools. So no Odd can `git init`, `git clone` or update a submodule at a granted folder's top. Claude Code's sandbox refuses every `.git/config` write even when set to allow it (2.1.318), so a Claude Code Odd cannot start a repository; a Codex Odd can, in a subfolder of its own folder. An Odd's git ignores the owner's global git settings and copies no sample hooks (`gitEnv`). Codex keeps each write folder's own `.git` read only by itself, so a Codex Odd cannot commit in a granted repository; a nested one is not covered for Codex, which takes a glob only to deny, and a deny stops git reading. A run of work another Odd handed over keeps this Odd's own Run commands, Browse the web and granted folders; the Draft cap on such runs covers outside tools only, since those are what leave the office. A folder deleted since it was given reaches no run. `checkFolder` refuses the home folder and a folder that holds or sits in a secret store (`SECRET_STORES`), the office's home or Oddboro's code, each with one line the page shows under the folder field, and a real path holding `*`, `?`, `[` or `]`, which Codex cannot take. It compares real paths as the disk spells them, so case, `~`, a link or `..` change nothing. `setFolder` also refuses a folder inside or holding one the Odd already has, since one would carry two levels; the same folder at another level replaces it. Every change is a Ledger line by the owner, like "Took ~/notes from Sam", and takes effect on the Odd's next run. Code in the ledger's `office.ts`, the office's `staff.ts` and `AccessTab.svelte`; `apps/office/CLAUDE.md` item 9 lists the rules. What commands read, and when they reach the internet, is in the 2026-11-05 decision on one access profile per Odd, which supersedes this one there. Folders outside the home: the 2026-11-08 ruling.
